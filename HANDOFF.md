# PART 5 — LOCAL SETUP (from an empty clone)

```bash
# 0. Clone
git clone <your-repo-url> PixelSearch && cd PixelSearch

# 1. ModelKit: regenerate the ONNX models + parity references (one time, ~5–10 min)
cd model_kit
python3 -m venv .venv && source .venv/bin/activate      # (Windows: .venv\Scripts\activate)
pip install -r requirements.txt
python prepare_model.py            # downloads MobileCLIP-S1, exports+patches ONNX, writes out/
python parity/gen_reference.py     # writes parity/reference_embeddings.json + images/
python parity/gen_tokens.py        # writes parity/reference_tokens.json
python eval/test_metrics.py        # -> "all metric tests passed"
deactivate && cd ..

# 2. Flutter app
cd pixelsearch_app
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # generates app_database.g.dart
flutter analyze                     # -> No issues found!
flutter test test/                  # -> All tests passed! (32)

# 3. Provide models to the app for on-device use (Android)
#    Ship model_kit/out/mobileclip_{image,text}_fp16.onnx to <app support>/models/ at runtime
#    (model-manager UI is M12, not built). For desktop/emulator dev you can push manually.

# 4. Run
flutter run                         # choose an Android device/emulator (grant photo permission)
#    On Android also register the WorkManager entrypoint in main() (see indexing_wiring.dart):
#      Workmanager().initialize(indexCallbackDispatcher);

# 5. (Optional) run the numerical gates on a real ONNX Runtime host (Linux desktop shown)
#    First edit the absolute k*Model/kVocab/kRef paths at the top of each integration_test file
#    to point at your model_kit/out and model_kit/parity, then:
sudo apt-get install -y libgtk-3-dev ninja-build clang cmake xvfb     # linux desktop deps
xvfb-run -a flutter test integration_test/image_parity_test.dart -d linux
xvfb-run -a flutter test integration_test/text_parity_test.dart  -d linux
xvfb-run -a flutter test integration_test/golden_validation_test.dart -d linux
xvfb-run -a flutter test integration_test/benchmark_test.dart -d linux
xvfb-run -a flutter test integration_test/semantic_search_test.dart -d linux   # M6: 6/6 retrieval + latency
```

## Technical debt (see `docs/TECHNICAL_DEBT.md`)
- TD-2 embeddings stored float32 (2 KB/photo) — fp16 blob halving if size hurts.
- TD-3 brute-force cosine — swap to sqlite-vec/ObjectBox when >50k.
- TD-4 web has no DB backend (native-only) — drift-wasm if web becomes a target.
- TD-6 thumbnails re-decoded on demand — bounded cache if scroll perf needs it.
- TD-9 preprocessing uses per-pixel `getPixel` — switch to `getBytes` buffer for indexing throughput.
- TD-10 tokenizer `basic_clean` approximates ftfy (verified exact on 19 cases).
- TD-11 M5 device adapters written but not runtime-tested (needs device).
- TD-12 M6 backend rebuilds once on index warm-up (embedder re-created; ORT session lazy) — benign.
- TD-13 M6 in-memory index isn't incrementally refreshed mid-session when the indexer adds embeddings.
- TD-14 M6 min-cosine (0.15) + hybrid weights are measured/heuristic defaults — tune on a labeled set (M14).

## Known issues (see `docs/KNOWN_ISSUES.md`)
- KI-2 fp16 models require an fp16 EP (NNAPI/XNNPACK) — the CPU EP cannot run fp16 (gates use fp32).
- KI-3 web build has no persistence backend (native-only by design).
- KI-4 `reference_vectors.json` absolute magnitudes are small (self-test L1 norm) — argmax is the target.
- KI-5 M6 semantic min-cosine is a small-sample heuristic (recall-favoring) — real tuning is M14.
- KI-6 M6 index warm-up is one-shot; new embeddings added mid-session aren't reflected until rebuild.
